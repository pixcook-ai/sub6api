# OpenAI 账号按请求多代理

普通 OpenAI OAuth 账号和独立的 OpenAI BPS 平台账号（`platform: openai_bps`）可在原代理入口选择「单代理」或「按请求分散」。管理员为每个账号选择现有代理；请求仅使用该账号选定的范围。账号总并发、模型权限和上游额度不随代理数量增加。

## 配置

1. 在代理管理中准备启用、未过期的代理。
2. 新增或编辑受支持的 OAuth 父账号，选择「按请求分散」及至少一个代理，保存后重新打开核对。
3. 恢复单出口时明确选择「单代理」，核对原 `proxy_id`。保存的组和原单代理值可以同时保留。

配置保存在现有账号 `extra` 中，无新增数据库表或迁移：

```json
{
  "openai_proxy_mode": "request",
  "openai_proxy_ids": [101, 102]
}
```

| 字段 | 行为 |
| --- | --- |
| `openai_proxy_mode` | `single` 使用原单代理路径；`request` 按逻辑请求选代理。显式新模式优先于旧 BPS 配置。 |
| `openai_proxy_ids` | 当前数据库内的代理 ID。新建或变更 request 组时必须非空，且所选代理均存在、启用、未过期。 |
| `openai_excel_bps_proxy_mode` / `openai_excel_bps_proxy_ids` | 兼容旧 BPS 配置；仅缺失新模式时读取，旧 request 只在独立 BPS 平台账号上启用。 |

缺失新字段沿用原行为。切回单代理必须保存 `openai_proxy_mode: single`；删除新模式字段可能重新启用旧 BPS request。未知或 null 模式、非法 ID、空 request 组在保存时拒绝，已存的无效 request 配置也不会自动退回直连。

旧表单不提交这些字段时保留原配置。组内代理后来失效时，允许不改变组的无关编辑或明确关闭 request；实际请求仍检查当前可用成员。PAT、Agent Identity、shadow、非 OAuth 账号及其他平台不支持此模式。

## 请求与租约

网关每个新的 HTTP/SSE 逻辑请求通过 `ProxyRepository.ListByIDs` 实时读取所选代理，过滤缺失、停用、过期和无效地址。数据库查询失败或全部成员不可用时返回明确错误，不使用原 `proxy_id`、直连或组外代理。本实现没有原 PR 的后台成员快照，也没有 15 秒刷新或 30 秒快照过期规则。

选择和占用在同一进程锁内完成：优先在途请求较少的出口，平局轮转，忙时可复用。计数按代理 ID 在进程内共享；一个账号不会因此获得额外并发额度。不同代理记录也不保证对应不同公网 IP。

HTTP/SSE 逻辑请求持有一次租约。请求内受支持的转发、修正和 token 刷新继承同一出口；结束、失败或取消后释放。已取得租约的请求不会因管理员修改代理配置而在中途改选出口。刷新重新读取账号后发现模式不再允许 request，或已选出口被移出组时，明确拒绝，不转向新的单代理或直连。此功能不增加已发送请求的跨出口重放。

OAuth 授权 session 固定已选出口；callback 复核它仍属于当前有效选择，不能换另一个代理兑换原授权码。独立 token 刷新和已适配的维护调用从账号组中选择有效出口，与另一次推理请求不保证相同出口。

## 备份与恢复

带代理导出时，账号顶层 `openai_proxy_keys` 保存新组，`bps_proxy_keys` 兼容旧组；`extra` 中的本地数字组 ID 被移除。组键是协议、主机、端口、用户名、密码的版本化 SHA256 身份，精确保留凭据中的空格和分隔符。single 模式保留的组也可恢复。

导入按目标库实际存在或实际创建的代理重新映射 ID，不以来源数字 ID 代替映射，也不信任文件中任意代理别名。身份碰撞、缺失组键或找不到对应代理会使该账号导入失败。普通单代理仍使用原 `proxy_key` 规则。

不导出代理不会自动关闭 request；导出的 request 账号缺少组键，不能直接作为直连账号恢复。导入沿用逐项处理，代理先于账号处理；账号失败时代理仍可能已经创建或更新。HTTP 200 表示批次完成处理，需核对 `AccountFailed`、`ProxyCreated`、`ProxyReused` 和 `Errors`。

代理关联数量表示保存的配置引用，包含单代理及生效模式对应的 request 组，同一账号去重。被引用的代理受删除保护；关联数量不表示实时流量或空闲度。

## 支持边界与升级

真实 WebSocket 的 request 路由尚未实现，会在建立连接前明确拒绝；受支持的 HTTP/SSE 路径不自动切换为 WS。本次迁移不引入 SIWC、Mihomo 或原仓库的托管授权连接体系；也不因代理设置增加原本不存在的协议、登录或维护能力。导入的 managed-connection 标记不能被同一次编辑清除后绕过 request 配置保护。

独立插件 RPC `ResolvePluginOutboundIdentity` 在 request 模式下明确拒绝：该 RPC 只返回出站身份，不能持有并管理后续请求的代理租约。正常主请求经宿主调用的 plugin transport 支持 request 模式，继承主请求已选定的出口和租约；独立 RPC 的限制不影响这条转发路径。

代理负载计数仅在单进程内有效。多实例各自选择，不保证集群全局最少在途，也不提供跨实例共享代理租约。共享账号与调度缓存的实例应统一升级，前后端使用同一整合版本；旧实例可能忽略新配置。账号调度快照的更新仍遵循现有缓存机制，实时代理目录读取不等于所有实例立即读取到最新账号配置。

回退前停止新请求并排空现有请求；在支持本功能的版本中明确切为已核对的 single，或停用相关账号，再回退程序。换回旧二进制不会撤销已保存的配置或导入结果。本功能无需新增数据库迁移，不代表同一发行版本的其他变更也无需迁移。
