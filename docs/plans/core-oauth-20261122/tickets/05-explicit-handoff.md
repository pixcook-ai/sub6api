# E：显式交接旧受管所有权并保持 toSub2 可选兼容

追踪：[pixcook-ai/sub6api#7](https://github.com/pixcook-ai/sub6api/issues/7)；父规格：[#2](https://github.com/pixcook-ai/sub6api/issues/2)。

## What to build

旧受管模式管理员可在清晰的所有权状态下选择保留旧模式、重新授权或执行受保护交接；交接完成后由 Sub6 独占刷新与发布，toSub2 仅作为可选管理客户端。

## Acceptance criteria

- [ ] 旧账号保持原有所有权，不自动接管或共享 RT；核心功能无需 toSub2 进程、安装或 Keychain。
- [ ] 交接显式建立旧所有者围栏、确认无在途刷新、受保护传递、撤销旧发布权并写持久回执；全程只有一个刷新和发布权威。
- [ ] 无法证明围栏/无在途/撤销/回执时闭锁，保留旧模式或要求重新授权；重启、重复请求和中途失败可恢复且不会双写。
- [ ] 可选 toSub2 管理接口明确核心 profile 与外部受管账号边界，缺核心能力时不隐式降级为共享 RT。
- [ ] 提供管理员操作、恢复和上游兼容说明，并注明手动停调、身份核对和真实凭据交接的验收边界。
- [ ] 合成故障路径与停止 toSub2 的核心路径有证据；未获真实凭据/操作授权时不执行真实迁移，不关闭相关真实验收项。

## Blocked by

- B：持久化核心授权及单写者。
- D：核心 runtime 所有权、快照与路由。

## Status

ready-for-agent；兼容合同可先核对，真实旧受管交接保持显式操作门。
